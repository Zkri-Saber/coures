تا ئێستا ڕاستەوخۆ commit ـت کردووە بۆ `main`، وەشانی سەرەکیی پڕۆژەکەت. ئەمە کێشە نییە کاتێک بە تەنها کار دەکەیت و گۆڕانکارییەکان بچووکن. بەڵام ئەگەر بتەوێت شتێکی مەترسیدار تاقی بکەیتەوە، یان چەند کەسێک لە یەک کاتدا کار دەکەن، چی؟ **branch** (لق) بەکاردەهێنیت.

## Branch چییە؟

Branch کۆپییەکی جیای پڕۆژەکەتە کە دەتوانیت گۆڕانکاری تێدا بکەیت بەبێ دەستلێدان لە `main`. کاتێک لە گۆڕانکارییەکان ڕازی بوویت، بە **pull request** داوا دەکەیت بهێنرێنە ناو `main` ـەوە.

```text
main           ●───●──────────────●   ← merged
                    \            /
readme-edits         ●────●────●
                   (your changes)
```

نزیکەی هەموو تیمێکی نەرمەکاڵا بەم شێوەیە کار دەکات، و پێی دەوترێت **GitHub flow**:

1. Branch ـێک دروست بکە
2. Commit لەسەری بکە
3. Pull request ـێک بکەرەوە
4. گفتوگۆ و پێداچوونەوە
5. Merge بکە بۆ ناو `main`

## هەنگاوی 1: Branch ـێک دروست بکە

1. ڕیپۆزیتۆریی `hello-world` لەسەر تابی **Code** بکەرەوە.
2. کلیک لە لیستی branch بکە کە دەڵێت `main`.
3. ناوێک بۆ branch ـەکەت بنووسە: `readme-edits`.
4. کلیک لە **Create branch: readme-edits from main** بکە.

GitHub دەتباتە سەر branch ـە نوێیەکە. دڵنیابە کە لیستی branch ئێستا دەڵێت `readme-edits`.

## هەنگاوی 2: لەسەر branch ـەکە commit بکە

1. `README.md` بکەرەوە و کلیک لە ئایکۆنی قەڵەمەکە بکە.
2. بەشێکی نوێ زیاد بکە، بۆ نموونە لیستێک لە سێ ڕاستی دەربارەی خۆت.
3. کلیک لە **Commit changes...** بکە، پەیامێک بنووسە، و commit بکە.

ئێستا لیستی branch بگۆڕە بۆ `main` و README بکەرەوە. بەشە نوێیەکەت لەوێ نییە: گۆڕانکارییەکە تا ئێستا تەنها لەسەر `readme-edits` هەیە.

## هەنگاوی 3: Pull request ـێک بکەرەوە

1. کلیک لە تابی **Pull requests** بکە.
2. کلیک لە **New pull request** بکە.
3. `readme-edits` هەڵبژێرە وەک ئەو branch ـەی لەگەڵ `main` بەراورد دەکرێت.
4. سەیری diff ـەکە بکە: ئەمانە ئەو گۆڕانکارییانەن کە پێشنیاریان دەکەیت.
5. کلیک لە **Create pull request** بکە.
6. ناونیشانێکی ڕوون و وەسفێکی کورت بدە بە چیت گۆڕیوە و بۆچی.
7. دووبارە کلیک لە **Create pull request** بکە.

> کورتەڕێ: دوای commit کردن بۆ branch ـێکی نوێ، GitHub زۆرجار شریتێکی زەرد پیشان دەدات کە دوگمەی **Compare & pull request** ی تێدایە. هەمان کار دەکات.

## هەنگاوی 4: پێداچوونەوە

Pull request گفتوگۆیەکە. لە تیمێکدا، کەسانی تر گۆڕانکارییەکانت لە تابی **Files changed** دا دەخوێننەوە، لێدوان لەسەر دێڕی دیاریکراو دادەنێن، و پەسەندیان دەکەن یان داوای گۆڕانکاری دەکەن. ئەگەر گۆڕانکاری پێویست بوو، تەنها commit ـی زیاتر لەسەر هەمان branch دەکەیت و خۆکارانە لە pull request ـەکەدا دەردەکەون.

تاقی بکەرەوە: لێدوانێک لەسەر pull request ـەکەی خۆت دابنێ.

## هەنگاوی 5: Merge

1. لە خوارەوەی pull request ـەکە، کلیک لە **Merge pull request** بکە.
2. کلیک لە **Confirm merge** بکە.
3. کلیک لە **Delete branch** بکە. کاری branch ـەکە ئێستا بە سەلامەتی لە `main` دایە، بۆیە ئیتر پێویستت پێی نییە.

تابی **Code** بکەرەوە: README ـەکەت لەسەر `main` ئێستا بەشە نوێیەکەی تێدایە.

:::quiz
Q: بۆچی لە جیاتی ڕاستەوخۆ لەسەر `main`، گۆڕانکاری لەسەر branch ـێک دەکەیت؟
- [ ] Branch ماڵپەڕەکە خێراتر بار دەکات
- [x] بۆ ئەوەی کار بکەیت و ڕا وەربگریت بەبێ گۆڕینی وەشانی سەرەکی تا ئامادە دەبێت
- [ ] GitHub ڕێگە بە commit بۆ `main` نادات
Why: Branch کاری تەواونەکراو یان تاقیکاری جیا دەکاتەوە. `main` تەنها کاتێک دەگۆڕێت کە merge دەکەیت.

Q: Pull request ـێکت کردووەتەوە، و مامۆستاکەت داوات لێ دەکات هەڵەیەکی ڕێنووس چاک بکەیت. چی دەکەیت؟
- [ ] Pull request ـەکە دادەخەیت و لە سەرەتاوە دەست پێ دەکەیتەوە
- [x] چاککردنەکە لەسەر هەمان branch commit دەکەیت؛ خۆکارانە لە pull request ـەکەدا دەردەکەوێت
- [ ] لە جیاتی ئەوە فایلەکە لەسەر `main` دەستکاری دەکەیت
Why: Pull request بەدوای branch ـەکەیدا دەڕوات. Commit ـە نوێیەکانی سەر branch ـەکە بۆی زیاد دەکرێن.

Q: Merge کردنی pull request ـێک چی دەکات؟
- [ ] گۆڕانکارییەکان دەسڕێتەوە
- [x] Commit ـەکانی branch ـەکە دەهێنێتە ناو `main`
- [ ] ڕیپۆزیتۆرییەکی نوێ دروست دەکات
Why: Merge گۆڕانکارییەکانی branch ـەکەت لەگەڵ branch ـی ئامانج، کە زۆرجار `main` ـە، تێکەڵ دەکات.
:::
