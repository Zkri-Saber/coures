In this lesson you'll create a GitHub account and your first repository. Everything happens in the browser; you don't need to install anything.

## Create your account

1. Go to [github.com](https://github.com) and click **Sign up**.
2. Enter your email, a strong password and a **username**.
3. Verify your email address when GitHub sends you a code.

Choosing a username:

- It appears in all your links, like `github.com/your-username`, so keep it short and easy to read.
- Pick something you'd be happy to show a teacher or employer. `sara-codes` is better than `xX_destroyer_Xx`.
- Don't include your birth year, phone number or other personal details.

> You must be at least 13 to have a GitHub account. Some countries require you to be older.

GitHub may also ask you to set up **two-factor authentication** (a code from an app on your phone each time you sign in). Say yes: it keeps your account safe even if someone learns your password.

## Create a repository

1. In the top-right corner of any GitHub page, click the **+** button, then **New repository**.
2. In **Repository name**, type `hello-world`.
3. In **Description**, write one sentence, like *My first repository, for practising GitHub*.
4. Choose **Public**. Anyone can see public repositories; only you (and people you invite) can see private ones.
5. Turn on **Add a README file**.
6. Click **Create repository**.

## A tour of your repository

Your new repository page has a few key areas:

- **The file list** shows every file and folder. Right now there's just `README.md`.
- **The README** is displayed below the file list. It's the front page of your project: the first thing visitors read.
- **The tabs** across the top (**Code**, **Issues**, **Pull requests**, **Settings** and more) are where you'll work in the next lessons.
- **The branch menu**, labelled `main`, shows which version of the project you're looking at.
- **The commit count** near the file list (for example *1 Commit*) opens the full history.

## README files use Markdown

`README.md` ends in `.md` because it's written in **Markdown**: plain text with a few symbols for formatting.

```markdown
# Big heading
## Smaller heading

Some **bold** text and some *italic* text.

- A bullet point
- Another one

[A link](https://github.com)
```

You'll edit your README in the next lesson.

:::quiz
Q: Who can see a public repository?
- [x] Anyone on the internet
- [ ] Only you
- [ ] Only people you invite
Why: Public repositories are visible to everyone. Private ones are only visible to you and people you invite, so never put personal information in a public repository.

Q: What is a README file for?
- [ ] It stores your GitHub password
- [x] It explains what the project is; GitHub shows it on the repository's front page
- [ ] It lists every commit ever made
Why: The README is the first thing visitors read, so it should explain what the project is and how to use it.
:::
